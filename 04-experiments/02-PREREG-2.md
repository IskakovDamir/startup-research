## 1. Требование к базовой ставке

```
0.005  ≤  π̂  ≤  0.03
```

Верхняя граница — «существенно ниже 0.062»: не повтор в той же точке, а вторая точка на оси. Нижняя граница — защита от вырождения: при слишком редком исходе ячейки почти все нулевые, `B̂ → 1` тривиально, и переворот проходит по причине, не имеющей отношения к утверждению.

Набор с `π̂` вне этого коридора **не используется**, каким бы удобным он ни оказался.

## 2. Сетка порогов — привязана к базовой ставке

Определяется после вычисления `π̂` и до вычисления чего-либо ещё:

```
ближняя сетка:  p_t ∈ { 0.50·π̂ , 0.75·π̂ , 1.00·π̂ , 1.50·π̂ , 2.00·π̂ }
дальняя сетка:  p_t ∈ { 0.10 , 0.20 , 0.30 , 0.50 }        (для сопоставимости с прогоном 1)
```

**«Вблизи базовой ставки» определяется здесь численно:**

```
N  :=  { p_t :  π̂/2  ≤  p_t  ≤  2·π̂ }
```

то есть в пределах двукратного отклонения от базовой ставки в обе стороны. Иные значения `p_t` не сообщаются.

## 3. Насколько это требование жёстко — выводится сейчас, а не после

При `p_t = π̂` расстояние `|π̂ − p_t| = 0`, и острая форма Скарфа даёт `U(π̂;σ) = σ/(2(1−π̂))`. Отсюда отношение

```
U_naive / U_ours  |_(p_t = π̂)   =   σ̂_naive / σ̂_ours   =   1 / √(1 − B_L)
```

Требование «отношение ≥ 2» **ровно в точке базовой ставки** эквивалентно

```
B_L  ≥  0.75
```

Внутри полосы `N` требование чуть слабее, потому что отношение растёт с удалением от `π̂`: оно меняется от `1/√(1−B_L)` в точке `π̂` до `1/(1−B_L)` на бесконечности.

**Это записывается до данных нарочно.** В прогоне 1 было `B_L = 0.5542`, что даёт в точке базовой ставки отношение `1.497` — и наблюдалось `1.535` при `p_t = 0.05`. То есть провал прогона 1 вблизи базовой ставки был **предсказуем из одной цифры**, и здесь заранее названо, какая цифра решает исход: `B_L`, а не базовая ставка сама по себе. Если новый набор даст `B_L < 0.75`, клауза R1′ почти наверняка не пройдёт, и это будет содержательным отрицательным результатом, а не неудачей выбора данных.

## 4. Клаузы непустоты — читаются на уровне чтения, и только на нём

- **R1′ — переворот вблизи базовой ставки.** Существует `p_t ∈ N` с `U_naive(p_t)/U_ours(p_t) ≥ 2`.
- **R2′ — защитимость там же.** При том же `p_t ∈ N` интервал переворота `[U_ours, U_naive)` пересекается с `δ ∈ [0.001, 0.05]`.
- **R3′ — режим.** `B_L ≥ 0.5` **и** `0.005 ≤ π̂ ≤ 0.03`.

**Область непуста вблизи базовой ставки ⟺ R1′ ∧ R2′ ∧ R3′.**

**Сообщается, но не требуется (строгая форма, объявляется сейчас, чтобы не выбираться потом):**
- **R1″** — то же самое ровно в точке `p_t = π̂`. Эквивалентно `B_L ≥ 0.75`. Проходит или нет — сообщается в обоих случаях.
- Полная таблица по дальней сетке — для прямого сопоставления с прогоном 1.

## 5. Клаузы исхода D

Первые три — из пререгистрации 1, без изменений. Последние две — новые.

- **D-a. Населённость.** Ни на одном уровне `occ ≥ 0.90` → исход D.
- **D-b. Ширина зажима.** На уровне чтения `B̂_cv − B̂_pi > 0.25` → исход D.
- **D-c. Вырождение вниз.** `B_L < 0.5` при узком зажиме → исход A на этом наборе, не D. Область пуста в любом случае.
- **D-d. Вырождение по редкости. НОВАЯ.** На уровне чтения доля выборочной массы в ячейках, содержащих **хотя бы один положительный исход**, ниже `0.50` → исход D. Смысл: при слишком редком исходе `B̂` определяется целиком нулевыми ячейками, и высокое `B̂` означает не неустранимость, а отсутствие положительных наблюдений. Это режим отказа, которого при `π̂ = 0.062` не было и который создаётся именно понижением базовой ставки.
- **D-e. Переворот есть, но не там. НОВАЯ.** Если `R1′` не выполнена, но переворот с отношением `≥ 2` существует на **дальней** сетке — результат сообщается как **«повтор картины прогона 1»**: область непуста, но не вблизи базовой ставки. Это **не** непустота в смысле этой пререгистрации и **не** подтверждение проверяемого утверждения. Формулировка фиксируется здесь: «на двух наборах данных из двух переворот доступен только при порогах, далёких от базовой ставки», и смягчать её нельзя.

## 6. Обработка дубликатов — объявляется, поэтому засчитывается

Вердикт берётся на данных **как есть**: строки не удаляются, дубликаты сохраняются.

**Дополнительно и обязательно** прогоняется вариант со схлопыванием точных дубликатов по объявленному набору признаков вместе с исходом, и его результат входит в отчёт по клаузам, а не в примечание. **Если под схлопыванием переворачивается любая из `R1′`, `R3′`, `D-b` — результат объявляется хрупким, и вердикт понижается до исхода D.** В прогоне 1 такая проверка была незарегистрированной и потому в отчёт не входила; здесь она объявлена заранее.

## 7. Правило выбора набора данных — чтобы выбор не был степенью свободы

Кандидат допускается, если выполнены **все** условия: публичный и загружаемый без регистрации; бинарный исход; **не менее пяти** природно категориальных признаков (без конструирования и без биннинга числовых); `n ≥ 100 000`; `0.005 ≤ π̂ ≤ 0.03`.

Среди допущенных берётся **кандидат с наименьшей базовой ставкой**. Ничьи разрешаются в пользу большего `n`.

**Ни один кандидат не отсеивается и не выбирается ни по какой оценке `B`, занятости ячеек после расчёта или предполагаемому исходу.** Скрининг ведётся только по `n`, `π̂`, типам признаков и доступности. Раздел 3 называет цифру, которая решает исход, — и именно поэтому она не входит в критерии отбора.

**Если ни один публичный набор не проходит** — это сообщается первой строкой отчёта и является исходом D другим путём. Набор данных под задачу не конструируется.
