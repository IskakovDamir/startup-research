## Блок 2 — декомпозиция (ядро)

### Вопрос

Какая доля дисперсии ошибки предсказания объясняется тем, **какой объект** предсказывают, и какая — тем, **каким методом**.

### Заранее объявленные исходы

**Исход A — ошибка принадлежит объекту.** Дисперсия ошибки в основном по объектам, слабо по методам. Тогда: потолок близок, улучшение моделей бессмысленно по построению, и это результат, убивающий целую исследовательскую программу.

**Исход B — ошибка принадлежит методу.** Дисперсия в основном по методам. Тогда: потолок далёк, поле не исчерпало возможности, и наш критерий развёртывания говорит «разворачивать, но выбирать метод». Тоже результат, просто другой.

**Исход C — смешанный, зависящий от конструкта исхода.** Если разложение меняется в зависимости от определения успеха (см. D2), то **это и есть главный результат**: предсказуемость не свойство фирм, а свойство пары «фирма, определение успеха».

Все три пишутся ДО расчётов. Ни один не является провалом.

## Наследуемые правила

Действуют правила из `../09-agents/AGENT-PROTOCOLS.md` основного волта (PI, 2026-07-17), в частности:

1. **Reference lists вне scope агентов.** В прозе только маркеры вида `[REF: Salganik 2020]`. Списки литературы собирает PI механически копированием из `01-literature/00-VERIFIED-SOURCES.md`. Генерация цитат = фабрикация.
2. **Внешняя атрибуция требует fetch в той же сессии,** с `[FETCH: url · дата]` на той же строке. Fetch прошлой сессии не является fetch. Нет fetch → нет кавычек, только помеченный парафраз.
3. **Никакой числовой конфабуляции.** Вероятность или точечная оценка сообщается только при наличии (а) референсного класса, (б) базовой ставки, (в) обновления с обоснованием. Иначе только порядковая оценка.

Корневая причина у всех трёх одна: под давлением произвести well-formed артефакт модель **достраивает шаблон** вместо того, чтобы сообщить измерение. Защита — не старательность, а либо замена генерации копированием, либо артефакт провенанса рядом с утверждением.
